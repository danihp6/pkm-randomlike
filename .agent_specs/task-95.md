- `chefstew` is the chef's dish. `below: [1, 1]` is what makes the shipped

  because `scripts/effect-coverage.mjs` reads `name: '…'` with a quote-terminated
  capture and an apostrophe would truncate it in the generated table.
- `smokeball` is absent from the generated dex, so its `shortDesc` is stated here
  (the same hand-authored precedent as `MEMORY_DRIVE_ITEMS`).

#### `src/engine/routes/npcs.ts`

All of these are pure: no Phaser, no DOM, no storage, no clock.

```ts
/**
 * The medic's one heal per floor. Reads the shipped mark
 * `npcUseId(mapIndex, roomIndex, 'medic')`: when it is already in `pickedItems`
 * the SAME `run` object comes back (a second talk heals nothing and writes
 * nothing, so a reload can never heal twice). Otherwise the result is
 * `markItemPicked(healParty(run), npcUseId(...))` — party and box, HP and PP,
 * never a resurrection and no status cure (that is the Pokevial's rule, D5).
 * Reads no RNG.
 */
export function medicHeal(run: RunState, mapIndex: number, roomIndex: number): RunState;

export type ChefTradeRefusal = 'no-member' | 'already-held' | 'no-berries';

export type ChefTrade =
  | Readonly<{
      ok: true;
      run: RunState;
      memberId: string;
      dishId: string;
      /** The berry ids actually spent, with multiplicity, in `BERRY_IDS` order. */
      berries: readonly string[];
    }>
  | Readonly<{ ok: false; reason: ChefTradeRefusal }>;

/**
 * Trades `CHEF_BERRY_COUNT` berries for one `CHEF_DISH_ITEM_ID`, equipped on
 * `memberId`. The berries are taken in `BERRY_IDS` table order, as many as each
 * stack holds before the next id is read, so the choice is data, never a roll.
 * Refusals, in this order: an unknown member (`no-member`), a member already
 * holding the dish (`already-held`), fewer than `CHEF_BERRY_COUNT` berries in the
 * bag (`no-berries`). On success: consume the berries, `addItem` the dish, then
 * `equipHeldItem` it (which returns the member's previous held item to the bag).
 * Reads no RNG.
 */
export function chefTrade(run: RunState, memberId: string): ChefTrade;

/**
 * The berries one shake gives: `Rng.int(BERRY_TREE_MIN, BERRY_TREE_CAP)` draws on
 * `Rng(hashSeed(`${seed}:npc:${roomIndex}:${npcId}:berries`))`, then one
 * `Rng.int(0, BERRY_IDS.length - 1)` per berry on the SAME stream.
 */
export function npcBerryHarvest(seed: string, roomIndex: number, npcId: string): readonly string[];

/**
 * The wild the shake wakes, through the room's own table and level roll:
 * `rollEncounter(table, rng, levelFor, 1)` — always a hit — where `rng` is
 * `Rng(hashSeed(`${seed}:npc:${roomIndex}:${npcId}:wild`))`. `undefined` only when
 * `table` is empty (the caller then starts no battle). Three draws on its own
 * stream; the room's grass, shiny and variant streams do not move.
 */
export function npcTreeWild(
  seed: string,
  roomIndex: number,
  npcId: string,
  table: EncounterTable,
  levelFor: EncounterLevelRoll,
): Encounter | undefined;

/**
 * One id out of `prizeIds`, on `Rng(hashSeed(`${seed}:npc:${roomIndex}:${npcId}:prize`))`,
 * or `null` for an empty list. Its own stream, so the stone a fixed seed pays never
 * depends on when the win happened.
 */
export function npcPrize(
  seed: string,
  roomIndex: number,
  npcId: string,
  prizeIds: readonly string[],
): string | null;

/** The stable `defeatedTrainers` id of an NPC's own battle: `npc-trainer-<mapIndex>-<roomIndex>-<npcId>`. */
export function npcTrainerId(mapIndex: number, roomIndex: number, npcId: string): string;
```

- `roomIndex` is the **room id inside the map** (`room.roomId`), the same value the
  shipped `roomNpc`, `npcSpot` and `npcUseId` calls take, so a revisit reads the
  same placement and the same mark.
- **Determinism (D11).** The three new streams are
  `${seed}:npc:<roomId>:<id>:berries`, `…:wild` and `…:prize`; the shipped
  `${seed}:npc:<roomId>` (presence + row), `…:spot`, `…:field` and `…:type` keep
  their formulas. **Adding four rolled rows to `NPC_ROWS` moves the presence total
  and the weighted row pick of the existing `${seed}:npc:<roomId>` stream**, so a
  fixed run's NPC placements change — a deliberate re-pin recorded here, not a
  defect; no other stream moves, and no shipped fixed-seed pin of `:field`/`:type`
  changes. The four new functions read no `run` object, so they cannot be reached
  from anywhere but their own NPC.
- Medic and chef draw no RNG at all.

#### `src/engine/battle/effects/items.ts`

```ts
/** A `flee` held item: the holder always escapes a wild battle (Smoke Ball). */
function fleeHandler(): NonNullable<EffectHandlers['onTryEscape']> {
  return (ctx) => {
    if (ctx.owner !== ctx.source) return;
    return true;
  };
}

// in handlersFor(), beside the other one-field handlers:
if (item.flee) handlers = { ...handlers, onTryEscape: fleeHandler() };
```

- Because the item now registers a handler, the shipped "registers every modelled
  held item" test passes without touching `UNMODELLED_ITEMS`; Magic Room and Klutz
  suppress the escape for free, since `ownedEffects` drops a suppressed item.

#### `src/engine/battle/runAway.ts`

```ts
/** True when an owned effect of `side`'s active grants the escape (Run Away, a `flee` item). */
function escapeGranted(state: BattleState, side: SideId): boolean;

export function canRun(state: BattleState, side: SideId): boolean;
//   = state.isWild && !isTrapped(state, side) && (!state.noFlee || escapeGranted(state, side))

export function rollRun(state: BattleState, side: SideId, rng: Rng = state.rng): boolean;
//   = false when canRun is false (so a noFlee wild with no grant records no attempt
//     and draws no odds);
//     the existing `runTryEscape(ctx)` check first — which is where both escape
//     exceptions land, so a granted escape is certain and consumes no odds draw;
//     otherwise the shipped odds roll and `escapeAttempts` bump, unchanged.
```

- `escapeGranted` builds one context with `makeContext(state, side, { source:

  `runTryEscape`. It is called from the RUN row's enable test (`BattleScene`,
  a HUD refresh, not a frame loop) and from `validateCommand`, so one small
  allocation per call is acceptable and the engine gains no second ability table.
- Trainer battles stay refused before any hook (`isWild` first), so a Run Away
  holder or a Smoke Ball holder still cannot flee a trainer.
