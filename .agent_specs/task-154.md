## 🎯 Scope

- **Task type:** engine rule + data + UI model + docs.
- **Role:** Dev.
- **Objective:** A run member can be **dark**. The run carries the flag on the member
  (`RunPokemon.dark`), the catch folds it in from a stream of its own, a dark member's
  primary ability is **Dark Matter** (`darkmatter`) and the ability the wild had rolled
  becomes its second slot — on the run member **and** on its battle snapshot, which
  `[Task-153]`'s `hasAbility`/`ownedEffects` already read. `SAVE_VERSION` becomes **25**
  with migration `24 → 25` seeding `dark: false` on every stored member. Both party
  render paths (Phaser canvas and the `D49` DOM card) paint the mark, the detail panel
  prints both ability names, and the rule is written into the two specs. **The mark
  needs no new player-facing string**: it is a tint on the row's portrait cell, and the
  second ability reuses the existing `detail.ability` key.
- **Environment:** worktree `../wt-pkm-154`, branch `task-154`.
- **Dependencies:** `[Task-151]` — `src/data/dex/customAbilities.ts` ships the
  `darkmatter` row (*Dark Matter* / *Materia Oscura*) and `getAbility('darkmatter')`
  resolves it; `[Task-153]` — `BattleFighter.secondAbility`, `FighterSnapshot.secondAbility`,
  `fighterAbilities(fighter)` and `hasAbility(fighter, id)` ship, and
  `ownedEffects` (`src/engine/battle/effects/registry.ts`) dispatches on both slots.
  Both are merged.

`src/engine/run/dark.ts` — **new**, pure, no Phaser, no DOM:

```ts
import { DARK_CHANCE } from '../../data/run';
import { hashSeed, Rng } from '../rng';
import { normalizeAbilityId } from '../battle/fighter';
import type { RunPokemon } from './progression';

/** The hand-authored ability id a dark member always carries. */
export const DARK_ABILITY = 'darkmatter';

/** The row's English name — what a fighter's `ability` field holds (the dex convention). */
export const DARK_ABILITY_NAME = 'Dark Matter';

/**
 * True when the wild caught under `catchId` is dark. Draws **only** from its own
 * stream, `hashSeed(`${seed}:dark:${mapIndex}:${routeInMap}:${catchId}`)`, so no
 * draw any other rule makes can move.
 */
export function isDarkCatch(
  seed: string,
  mapIndex: number,
  routeInMap: number,
  catchId: string,
): boolean;

/**
 * The member made dark: `fighter.ability` becomes `DARK_ABILITY_NAME`, the ability it
 * already had becomes the second slot (on the member **and** on the snapshot), and
 * `dark` becomes `true`. A member that is already dark comes back as the same object.
 */
export function asDark(member: RunPokemon): RunPokemon;
```

Rules:

- `isDarkCatch` = `new Rng(hashSeed(\`${seed}:dark:${mapIndex}:${routeInMap}:${catchId}\`)).next() < DARK_CHANCE`.
  It advances no shared stream; it mints its own `Rng`, like `battleSeed`.
- `asDark`: `member.dark === true` ⇒ return `member` (**same reference**, the data
  table's no-op convention). Otherwise
  `const primary = member.fighter.ability;`
  `const rolled = normalizeAbilityId(primary) === normalizeAbilityId(DARK_ABILITY_NAME) ? null : primary;`
  `const granted = rolled ?? member.secondAbility ?? null;`
  and return a member with `dark: true`, `fighter.ability = DARK_ABILITY_NAME`,
  `fighter.secondAbility = granted` and `secondAbility = granted` — each of the two
  `secondAbility` writes **only when `granted !== null`**, never an empty string.
- **Determinism:** `isDarkCatch` reads one `Rng` minted from `hashSeed`; `asDark`
  reads no RNG at all.

`src/engine/run/resolve.ts` — the catch fold (`resolveBattle`, the `result.captured`
block, currently lines 92-106). Read the id **once** and use it for both the member
and the roll:

```ts
const catchId = nextMemberId(next);
const keyed: RunPokemon = { ...base, fighter: { ...base.fighter, id: catchId } };
const adopted = adoptAtLevel(keyed, squadLevel(next), next.seed);
const caught = isDarkCatch(next.seed, next.mapIndex, next.routeInMap, catchId)

```

`src/engine/save.ts`:

- `export const SAVE_VERSION = 25;`
- a new migration key `24` in `SAVE_MIGRATIONS` (the table's shape is
  `Record<number, Migration>`, each step `(document) => ({ ...document, version: n + 1, … })`):

```ts
  // The dark Pokémon (`Task-154`): a v24 run predates the flag, so every stored
  // member starts not-dark; the decoder drops the `false` on the next write.

    ...document,
    version: 25,

```

- the helper beside `withCapturedRooms`/`withPcCatch`, in the file's own style
  (`{ dark: false, ...entry }`, the `6:` migration's precedent, so a field that
  already exists would win):

```ts
/** Writes `dark: false` on every member a v24 run stored (party, box and rip). */
function withDarkFlag(run: Record<string, unknown>): Record<string, unknown> {
  const mark = (list: unknown): unknown =>
    Array.isArray(list)
      ? list.map((entry) => (isRecord(entry) ? { dark: false, ...entry } : entry))
      : list;
  return { ...run, party: mark(run.party), box: mark(run.box), rip: mark(run.rip) };
}
```

- the big `SAVE_MIGRATIONS` doc comment gains its `24` clause, in the same voice as
  the `23` clause above it.
- `parsePokemon` (save.ts, the function that builds a `RunPokemon`) reads the flag the
  way `shiny` is read — **only when true**, so a round trip stays byte-stable:
  `...(value.dark === true ? { dark: true } : {})`.
